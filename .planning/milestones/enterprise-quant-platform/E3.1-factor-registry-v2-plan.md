# Phase E3.1：Factor Registry V2 Plan

## 目标

把因子从“列表展示”升级为“可组合策略的契约层”。以后从外部知道一个因子，可以先沉淀为 Factor Contract，明确数据依赖、as-of 要求、输出字段、频率和校验规则，再进入因子计算和策略组合。

## 非目标

- 不新增 Alpha 因子。
- 不实现因子计算 Runner。
- 不改变现有策略收益逻辑。
- 不修改 M0/M3/M4。
- 不做机器学习或参数优化。

## 必须表达的元数据

1. 基础信息
   - factor_id
   - name
   - category
   - direction
   - source

2. 时点安全
   - as_of_policy
   - as_of_field
   - effective_date_field
   - lag_days

3. 数据依赖
   - input_datasets
   - input_fields
   - dependencies

4. 输出契约
   - frequency
   - value_type
   - output_fields
   - validation rules

5. 生命周期
   - status
   - version
   - owner

## 实现任务

1. 新增 `factor_contracts` 表。
2. 新增 `runtime/factor_registry_repository.py`。
3. `SystemRepository` 组合新 mixin。
4. 提供：
   - `upsert_factor_contract()`
   - `load_factor_contract()`
   - `list_factor_contracts()`
   - `validate_strategy_factor_contracts()`
5. 对财务数据因子强制要求 as-of 字段。

## 验收标准

- Quality 因子可以表达 `f_ann_date` as-of。
- 价格/动量因子可以表达交易日时点口径。
- 策略实例能检查自身使用的因子是否具备契约。
- 缺失 as-of 的财务因子不能登记为正式因子契约。
