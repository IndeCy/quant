# Phase E2.2：Data Quality Gate Plan

## 目标

在每日生产流水线中加入统一数据质量门禁。数据更新成功之后、策略批处理之前，必须检查关键数据源是否可信；不可信时阻断策略运行，避免用旧数据、缺复权数据或坏库生成调仓建议。

## 非目标

- 不新增外部数据源。
- 不改变 Tushare 更新逻辑。
- 不修改策略、因子和回测逻辑。
- 不做复杂数据血缘平台。
- 不对历史全量数据做昂贵逐行扫描。

## 第一版门禁范围

1. Data Catalog 刷新必须成功。
2. 关键数据源必须存在且状态为 `OK`。
3. 关键表必须存在。
4. 关键表最新日期不能早于本次流水线要求的最小日期。
5. A 股行情必须包含日线和复权因子。
6. 基准数据必须包含 ETF 日线、ETF 复权因子和指数日线。

## 默认关键数据源

- `live_market_increment_duckdb`
  - `daily`
  - `adj_factor`
- `benchmark_increment_duckdb`
  - `fund_daily`
  - `fund_adj`
  - `index_daily`

## 生产流水线接入点

```text
data_update
  -> data_quality_gate
  -> strategy_batch
  -> notification
```

如果 `data_quality_gate` 失败：

- 不运行策略批处理。
- `daily_trading_pipeline` 标记为 `FAILED`。
- 运行步骤写入 `strategy_run_steps`。
- Bark 通知说明“数据质量失败，策略未执行”。

## 实现任务

1. 新增 `runtime/data_quality_gate.py`
   - 定义 `DataQualityRule`。
   - 实现 `run_data_quality_gate()`。
   - 输出结构化检查结果。

2. 接入 `runtime/daily_pipeline.py`
   - `data_update` 后执行门禁。
   - 门禁失败则阻断 `strategy_batch`。

3. 接入本地 API
   - `POST /api/data/quality-gate`

4. 补充测试
   - 门禁通过。
   - 缺失关键复权表失败。
   - 最新日期过旧失败。
   - 日流水线在门禁失败时不跑策略。
