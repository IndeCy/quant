# Phase E1.2：Walk-Forward Validation Plan

## 目标

把现有散落在研究脚本中的 Walk-Forward 验证沉淀为系统能力，支持后续任何策略或风险层参数研究都能按同一规则做样本外验证。

## 非目标

- 不修改 Quality Alpha 因子。
- 不新增策略。
- 不优化收益。
- 不改 M0/M3/M4 执行逻辑。
- 不在单测中依赖真实行情或重型回测。

## 固定选参规则

1. Sharpe 最高。
2. Calmar 最高。
3. 最大回撤更小。
4. 平均仓位更高。

验证集只能评估训练集已经选出的参数，禁止使用验证集结果反向调整参数。

## 实现任务

1. 新增 `runtime/walk_forward.py`
   - 定义 `WalkForwardWindow`。
   - 实现 `select_best_parameter()`。
   - 实现 `run_walk_forward_validation()`。
   - 实现 `run_walk_forward_experiment()` 并登记 Experiment Runner 产物。

2. 新增 `scripts/run_walk_forward_experiment.py`
   - 从 CSV 和窗口 JSON 读取输入。
   - 输出实验 run 信息。

3. 新增 `tests/test_walk_forward.py`
   - 覆盖固定排序规则。
   - 覆盖训练集选参、验证集冻结参数。
   - 覆盖实验产物登记。

```bash
/Users/admin/recommend_analysis/.venv/bin/python3 -m pytest tests/test_experiment_runner.py tests/test_walk_forward.py -q
```

## 预期结果

- Walk-Forward 不再只是某个 example 脚本的私有逻辑。
- 实验结果写入 `runs/experiments/<experiment_id>/...`。
- 实验定义、运行和产物写入 `state/quant_system.sqlite`。
- 后续前端研究模块可以统一读取实验列表与产物。
