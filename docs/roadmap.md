# 项目路线图

## Phase 1：数据可信 + 回测可信

- 状态：已完成验收
- 目标：
  - 回测按交易日推进。
  - 默认 T 日信号，T+1 交易日成交。
  - 成交统一走 `ExecutionModel`。
  - 停牌、涨跌停、缺失价格等不可交易场景保守拦截。
  - 输出总交易成本和成交失败次数。

## Phase 1.5：数据可信增强

- 状态：已实现并通过测试
- 优先级：P0
- 定位：承接 Phase 1，继续补齐低频 A 股多因子系统最容易出偏差的基础数据语义。该阶段只增强数据可信边界，不进入 Phase 2 因子开发，不做组合构建，不做自动下单。

### 1. 接入真实 A 股交易日历

- 背景：
  - Phase 1 已有轻量交易日历，但默认依赖工作日或已加载行情日期集合。
  - A 股真实交易日存在春节、国庆、临时休市、调休等特殊日期，不能长期用工作日近似。
- 目标：
  - 建立真实 A 股交易日历接口。
  - 支持沪深北交易所统一日历查询。
  - 支持本地缓存，避免每次回测重复请求外部接口。
  - 回测引擎继续只依赖统一 `TradingCalendar` 接口，不直接耦合数据源。
- 建议交付：
  - `data/calendar.py` 扩展真实日历加载能力。
  - 本地交易日历缓存表或文件。
  - 单测覆盖节假日、周末、调休、区间交易日列表。
- 验收标准：
  - 周末不交易。
  - 法定节假日不交易。
  - 调休工作日若非交易日，不被误判为交易日。
  - T 日信号能顺延到真实下一个交易日。

### 2. 明确复权口径

- 背景：
  - Phase 1 schema 已预留 `adj_factor`，但尚未强约束前复权、后复权、不复权在不同场景的使用。
  - 回测信号、成交估值、模拟盘盯市如果混用复权口径，会造成收益和交易价格失真。
- 目标：
  - 明确项目默认复权口径。
  - 区分策略研究用价格、真实成交用价格、持仓估值用价格。
  - 数据缓存 key 必须包含复权口径。
  - 回测结果报告应记录复权口径。
- 建议规则：
  - 策略信号默认使用前复权价格，便于历史连续性。
  - 模拟盘和真实成交价格默认使用不复权价格。
  - 回测成交模型默认使用指定 execution price 数据源，禁止隐式混用。
  - 同一次回测必须记录 `adjust` 参数。
- 建议交付：
  - 复权口径枚举或常量定义。
  - 缓存与 DataManager 的复权字段校验。
  - 回测结果记录复权口径。
  - 单测覆盖不同复权口径不可混用。
- 验收标准：
  - 同一标的同一区间可区分 `none/qfq/hfq`。
  - 回测必须能追溯使用的复权口径。
  - 策略信号价格和成交价格的口径差异有显式配置。

### 3. 定义财报披露日/as-of 数据接口

- 背景：
  - Phase 2 将进入价值、质量、红利因子，核心风险是财报未来函数。
  - 不能用报告期日期直接代表市场可见日期，必须使用披露日或公告日。
- 目标：
  - 定义财务数据 as-of 查询接口。
  - 所有财务字段必须带 `report_period` 和 `publish_date`。
  - 因子计算只能读取 `publish_date <= trade_date` 的最新可见数据。
  - 先定义接口和测试契约，不在 Phase 1.5 里实现复杂因子。
- 建议接口：
  - `get_financial_snapshot(symbol, trade_date)`
  - `get_financial_series(symbol, start_date, end_date, as_of=True)`
  - `get_latest_report(symbol, trade_date, fields)`
- 必备字段：
  - `symbol`
  - `report_period`
  - `publish_date`
  - `statement_type`
  - `field_name`
  - `field_value`
  - `source`
- 验收标准：
  - 若某财报 `publish_date` 晚于回测日期，则该日期不可见。
  - 同一交易日只返回当时已经披露的数据。
  - 单测必须覆盖“报告期已结束但尚未披露”的未来函数场景。

### Phase 1.5 不做事项

- 不开发价值、质量、红利等因子。
- 不做组合构建。
- 不做调仓清单。
- 不做自动下单。
- 不做复杂前端。

## Phase 2：补齐因子和策略模块

- 状态：待开始
- 前置依赖：Phase 1.5 完成真实交易日历、复权口径、财报 as-of 接口定义。
- 目标：
  - 建立价值、质量、红利、动量因子模块。
  - 实现因子标准化、分位数打分和基础因子检验。
  - 在不引入未来函数的前提下构建月频多因子策略。
