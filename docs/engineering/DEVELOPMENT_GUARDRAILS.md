# 量化系统开发围栏

## 目标

围栏服务于四件事：数据可信、回测可信、策略可解释、实盘可执行。它不用于追求目录整齐，
也不能成为修改 Alpha、M0 或历史结果的理由。

## 不可破坏的业务约束

1. 日线价格统一使用 qfq，口径变化必须创建新版本并重新验证历史结果。
2. 财务因子只能通过 as-of 门面读取，公告日不得晚于信号日。
3. 信号日与成交日分离，默认 T 日信号、T+1 交易日成交。
4. 成交必须经过 M0 ExecutionModel 或 Paper Broker，策略不得直接修改持仓。
5. 停牌、涨停买入、跌停卖出、成交价缺失或非正数时不得成交。
6. 策略只输出信号；组合构建决定权重；风险层只调整目标暴露。
7. 回测、Paper 和 Shadow Live 必须复用同一策略定义和数据口径。
8. 耗时研究必须先申请研究运行指纹；相同口径和数据快照默认复用，禁止通过改名绕过去重。

## 唯一运行入口

日常交易任务的调度、API、命令行和手工补跑必须调用 `PipelineService`。业务实现可以拆分为
多个步骤，但不得再创建功能相同的旁路脚本。每次运行必须保存 run_id、交易日、触发来源、
代码版本、数据版本、状态和错误信息。

## 代码边界

- `data/`：数据契约、清洗、复权、交易日历、as-of 和外部数据增量同步。
- `factors/`：因子计算，不决定持仓和成交。
- `strategies/`：信号生成和策略适配，不调用调度器、API 或 Broker。
- `portfolio/`：权重和组合构建。
- `risk/`：仓位约束和风险覆盖层。
- `backtest/`：可信回测与 M0 执行语义。
- `runtime/`：调度、Pipeline、持久化和运行编排。
- `api/`：查询和触发标准应用服务，不直接运行策略实现。
- `frontend/`：只访问 API，不读取本地数据库和运行目录。

## 版本规则

- 策略定义一旦产生运行记录，不得原地改变其业务含义。
- 因子、过滤条件、组合构建、风险层或执行口径变化时必须提升策略版本。
- 数据库 Schema 变化必须通过 `runtime/migrations/` 中的迁移脚本完成。
- M0 受保护文件发生变化时必须运行 M0 专项回归并取得用户确认。

## 禁止事项

- 在公共模块中按具体 strategy_id 编写特殊分支。
- 让前端从 DuckDB、SQLite、JSON 报告或 `runs/` 目录拼装业务状态。
- 把 Markdown、CSV 或 HTML 报告作为下一次计算的事实来源。
- 在数据更新失败、基准缺失或复权因子缺失时继续运行策略。
- 提交环境密钥、运行数据库、日志、缓存或每日生成产物。
- 未经确认自行降级实现、绕过失败门禁或改变既有策略语义。
- 在加载研究大表或启动回测后才登记实验，或只保存成功结论而丢弃失败尝试。

## 完成标准

每次改动必须说明影响模块、是否触碰 M0/策略/Schema、验证命令和剩余风险，并通过
`./scripts/verify.sh`。自动检查与本文冲突时，以更严格者为准；确需例外时记录 ADR 并由用户确认。
